# CL002 — Environment drift

- **Severity:** Warning
- **Confidence:** High

## What it finds

A configuration key that is introduced by one environment-specific file (e.g. `appsettings.Development.json`) but is missing from another environment's effective configuration.

## Why it matters

This is the classic "works in Development, crashes in Production" bug. A feature is developed against a key that only exists in the Development file; the Production deployment never sees it and fails at runtime — often days later, on the first code path that reads the key.

## Semantics

CL002 follows the layering of Microsoft.Extensions.Configuration: the effective configuration of an environment is `appsettings.json` overridden by `appsettings.{Environment}.json`.

- A key in the **base file** is available to every environment. It never drifts, and an environment file overriding it is fine.
- A key that exists **only in environment files** must exist in every environment in scope. Each environment where it is missing produces one finding.
- The environments in scope are the ones passed via `--environments`; without the flag, all environments discovered from the file names are compared.

## Example

```jsonc
// appsettings.Development.json
{ "Features": { "EnableBetaSearch": true } }

// appsettings.Production.json
{ }
```

> CL002: Configuration key 'Features:EnableBetaSearch' is defined for environment 'Development' but missing for environment 'Production'.

## How to fix

- Add the key to the environment files where it is missing, **or**
- move it to the base `appsettings.json` if the value applies to all environments, and override it only where it differs.
