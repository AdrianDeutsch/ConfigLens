# CL001 — Missing key

- **Severity:** Error
- **Confidence:** follows the resolution of the code access (literal = High, const/`nameof` = Medium, syntax-only = Low)

## What it finds

A configuration key that is read in code (`IConfiguration["…"]`, `GetValue<T>`, `GetConnectionString`) but does not exist in the effective configuration of one or more environments in scope.

## Why it matters

The read returns `null` (or the type default) at runtime — usually far from the place that misconfigured it, and often only in the one environment where the key is missing.

## Semantics

- The effective configuration of an environment is `appsettings.json` overridden by `appsettings.{Environment}.json`; a key present in the base file exists for every environment.
- A key that only exists as a **section prefix** (it has child keys) is not reported: the path exists, reading it as a value is a different smell.
- Section reads (`GetSection`) and options bindings are not checked here — a missing bound section is [CL006](CL006.md).
- If no configuration files were found at all, the rule is silent instead of flagging every read.

## Example

```csharp
var host = config["Database:Host"]; // CL001 if no configuration source defines Database:Host
```

## How to fix

Add the key to `appsettings.json` (or the affected environment files), or remove the read. If a near-miss key exists, [CL007](CL007.md) will point at it.
