# CL003 — Dead configuration

- **Severity:** Info
- **Confidence:** Medium; degrades to Low when the scan hit unresolvable key accesses (CL900)

## What it finds

A configuration key that no scanned code reads — neither directly, nor through an enclosing `GetSection` read, nor through an options binding.

## Why it matters

Dead keys accumulate, mislead during incident debugging ("we set it, why doesn't it work?") and hide real configuration behind noise.

## Semantics

- Keys under a section that code reads or binds (`GetSection("Smtp")`, `Configure<SmtpOptions>(…)`) count as used.
- Framework-consumed prefixes are excluded: `Logging`, `AllowedHosts`, `Kestrel`.
- Each key is reported once, even when it appears in several environment files.
- When the scan contains CL900 notes, any key might be read dynamically — findings degrade to Low confidence instead of claiming certainty (ADR-0002).
- If the scan observed no reads at all (no code side), the rule is silent.

## Example

```jsonc
{
  "Features": { "Legacy": true } // CL003 if nothing reads Features:Legacy
}
```

## How to fix

Delete the key, or wire it up in code. If it is consumed by an external system or reflection, record it in the baseline.
